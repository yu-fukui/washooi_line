# 参考記事メモ：「いつものLINEトークで動くAI秘書。作り方を画面つきで全部まとめました」

- 出典: Brain（brain-market.com/u/hanuha）、2,980円の有料記事（手順書 v1.0、2026/10/9 公開）
- 記録日: 2026-10-11
- ※ 記事は「購入者本人のためのもの・再配布禁止」とあるため、本文の転載はせず要点のみ記録する

## 要約

### 背景
- 代表と秘書の連絡は普段から LINE。Slack 等を入れても LINE に戻ってしまう
- 「新しいツールを覚えてもらう」のではなく、**いつものLINEトークに bot を入れて事務を手伝わせる**方針

### 仕組み
- LINE（Messaging API）→ Google Apps Script（Webアプリとして公開した Webhook 受け口）→ 必要なときだけ Claude API
- 「ありがとう」「了解です」などの**決まったあいづちは AI を呼ばずにルールで処理**し、費用を抑える
- 依頼一覧・ToDo・メモはスプレッドシートに保存

### 実際に任せていること（クライアント現場）
- 「領収」と送ると領収書PDFを作成→Googleドライブに保存→リンクを返す（月5〜10件、1件5〜10分の作業が不要に）
- PDF書類を決まった保存先に整理／必要なPDFを探す
- 1対1トークでスケジュールのリマインド
- 予定を伝えると Google カレンダーに登録
- メッセージを「依頼として処理」か「会話として返す」かに振り分け
- 約3日で12版→21版まで、現場の反応を見ながら修正（「この言い方だと伝わらない」「ここでは返事しなくていい」等）

### 運用ルール
- **作業はbotに、判断は人に**。お金・取引に関わる判断は人がする
- 確認が必要な処理は途中で人の確認をはさむ。転送は了承を得てから
- 手順が決まっている作業から任せる

### 費用
- 月1,000円以内を目安に管理、実績は月約500円。中心は Claude 利用料
- 簡単な仕分けは安いモデル、あいづちは AI を呼ばない
- **利用額が一定額を超えたら自分のLINEに通知**する仕組みを入れている
- Anthropic Console は少額チャージ＋自動リロードはオフ推奨

### 手順書（STEP 1〜9）の要点
1. LINE公式アカウント作成（アカウント名は後から変えにくい）
2. Messaging API を有効化（プロバイダーは後から変えられない）
3. LINE Developers でチャネルアクセストークン（長期）と自分のユーザーIDを控える
4. 応答メッセージをオフ（二重返信を防ぐ）
5. Apps Script にコードを貼る
6. トークンはコードに直書きせずスクリプトプロパティに保存
7. Webアプリとしてデプロイ（アクセス＝全員。修正時は「新バージョン」で再デプロイしないとURLが変わる）
8. Webhook URL を登録して疎通確認（GASは検証で302が出るが正常）。自分のユーザーIDで利用者を制限
9. Claude API をつなぐ（system プロンプトで口調・役割を変えられる）

### 注意事項
- 個人情報・パスワード・銀行情報は bot に送らない（ログに残る）
- トークン・APIキーは人に見せない／スクショに写さない
- プッシュは月の通数上限あり、返信は通数に数えない。グループへの送信は人数分カウント
- Claude に送った内容は Anthropic に送られる。取引先名や金額を含む場合は関係者に伝えておくと安心
- Apps Script の持ち主の Google アカウントは2段階認証を

### 自動化の候補を選ぶための「5つの書き出し」
1. 事務の頼みごとは、いつもどこで誰に頼んでいるか
2. 同じ手順で繰り返している作業は何か
3. 1回何分かかっているか
4. 月に何回発生しているか
5. 面倒だと感じる作業
→ 回数が多く手順が決まっている作業が bot に任せる候補

### 活用例（12個）
やることメモ／毎朝・毎夕のお知らせ／領収書・請求書の自動作成／領収書の写真を経費に記録／書類さがし／よくある質問への自動返信／申込・予約の受付通知／月初・月末のリマインド／確認依頼のやりとり／売上・集計のお知らせ／チームへの一斉連絡／文章の下書き・要約

## washooi_line との比較

| 観点 | 記事の bot | washooi_line |
|---|---|---|
| 基盤 | Google Apps Script＋スプレッドシート | Supabase（Postgres＋Edge Functions＋pg_cron） |
| 入口 | 1対1／グループで話しかける | 案件グループの会話を自動で読む＋1対1で指示 |
| AIの使い方 | 必要なときだけ。あいづちはルールで処理 | 案件会話は15分ごとにまとめて解析（Opus）、1対1の文章は Haiku |
| 人の確認 | お金・取引・転送は人の確認 | 中程度の確度は「候補」、削除は確認ボタン |
| 費用管理 | 上限目安＋超過時にLINE通知 | 未実装（利用量を記録していない） |
| 予定 | Google カレンダー登録・リマインド | 期限の表示のみ（毎朝6時の通知） |
| 書類 | PDF作成・保存・検索 | なし（会話中のURLは保存されているが検索できない） |

## washooi_line に活かせること（検討結果）

### すぐ効く（小さな変更）
1. **AI利用額の記録と上限アラート**：Claude を呼ぶたびに `usage`（入出力トークン）を記録し、月の推定額が設定額（例: 3,000円）を超えたら1対1トークに1回だけ知らせる。いまはいくら使っているか分からない
2. **あいづちはAIを呼ばない**：1対1の「ありがとう」「了解」「OK」、スタンプだけの発言などは Haiku を呼ばずに無視する。案件チャットでも、解析の前に「ありがとうございます」だけの発言を除くと Opus の入力が減る
3. **資料・リンクさがし**：案件チャットに貼られた Dropbox／ギガファイル便／Google Drive／YouTube のURLは既にデータベースに残っている。「リンク 波多野」で、その案件の最近のリンクを日付・送り主つきで返す

### 中くらい
4. **Google カレンダー追加ボタン**：撮影など日時のあるタスクの詳細に「カレンダーに追加」ボタン（Google カレンダーの予定作成リンク）を付ける。Google の認証設定が不要
5. **一定時間後の確認リマインド**：「確認待ち」が何日も続いているタスクを朝の通知で強調する（例: 3日以上で「⏳3日」）

### 将来の拡張（必要になったら）
6. 請求書・見積書のPDF作成（記事の領収書と同じ考え方）
7. 1対1での個人リマインド（プッシュ通数とのバランスを見て）

### 運用面で取り入れたい考え方
- 「作業はbotに、判断は人に」：完了・削除など取り消しにくい操作は確認をはさむ方針を続ける
- 現場の反応を見て短い間隔で直す（今のやり方を続ける）
- 案件チャットの内容が Claude に送られることは、必要に応じて関係者に伝えておく
