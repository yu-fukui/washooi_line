# LINE案件チャット タスク自動記録ボット 設計書（v4）

## 1. コンセプト

- 各**案件チャットにボットを入れておくだけ**。メンバーは普段通り会話し、コマンドは不要。ボットは案件チャットでは発言しない。
- 1つの案件に**複数のチャット**（制作チーム用、クライアントとのやり取り用など）をまとめられる。
- ボットは会話を読み取り、**AI（Claude）が「誰が・何を・いつまでに」を抽出してタスクとして記録**する。
- 結果は**管理用のメインチャット（LINEグループ）に毎朝6時にまとめて通知**する。
- 「送りました」「対応済みです」などの発言から**完了も自動で検知**する。チャットをまたいでも判定する（クライアントチャットの依頼 → 制作チャットの完了報告）。

```
 案件「ABC社 サイト制作」
   ├ 制作チャット ──────┐
   └ クライアントチャット ─┤
 案件「D社 LP」           ├─(会話)─▶ ボット ─▶ AI抽出 ─▶ DB ─▶ メインチャット（管理用グループ）
   ├ 制作チャット ──────┤     ※案件チャットには発言しない          ・新規/完了/変更の通知（毎朝6時）
   └ クライアントチャット ─┘                                        ・候補の確認ボタン
                                                                   ・6時の回は全案件サマリー付き
```

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| メインチャット | 管理用のLINEグループ |
| 通知頻度 | 1日1回。6:00（前回以降の更新＋全案件の未完了サマリー）を1プッシュにまとめる（当初の18:00の回は停止） |
| AIモデル | Claude Opus 5.5（`claude-opus-5-5`） |
| 案件チャットでの告知 | しない（ボットは案件チャットで一切発言しない） |
| 自動登録 | 確度が高いものは自動登録。中程度は「候補」としてボタンで確認 |
| 会話データの保存期間 | 1年（毎日、1年を過ぎた会話を自動削除） |
| 1案件の複数チャット | 案件 ─< チャット（種別: 制作 / クライアント）の構造。AIは案件内の全チャットをまとめて解析 |

## 3. 全体構成

```
 ┌──────────────┐ Webhook  ┌────────────────────────┐
 │ LINEグループ群 │────────▶│ line-webhook            │ 案件チャット: 会話を保存（即200応答）
 └──────────────┘◀────────│                          │ メインチャット: コマンド・ボタンに返信
                  返信(無料) └───────────┬────────────┘
                                       ▼
                            ┌────────────────────────┐
                            │ Supabase Postgres        │
                            └───────────▲────────────┘
            pg_cron 15分ごと             │
                            ┌───────────┴────────────┐     ┌────────────┐
                            │ extract                  │────▶│ Claude API  │
                            └────────────────────────┘◀────│ (JSON出力)  │
            pg_cron 毎朝6時                                   └────────────┘
                            ┌────────────────────────┐ Push
                            │ notify（6時はサマリー付き）│──────▶ メインチャット
                            └────────────────────────┘
```

| 要素 | 技術 |
|---|---|
| Webhook・定期処理 | Supabase Edge Functions（Deno / TypeScript） |
| DB | Supabase Postgres（RLS有効、Edge Functions から service_role で接続） |
| 定期実行 | pg_cron + pg_net |
| AI | Claude API（既定 `claude-opus-5-5`、構造化出力でJSONを受け取る） |

## 4. 案件とチャットの対応付け

1. ボットをグループに招待すると、**グループ名で案件が自動作成**され、そのチャットが紐付く（設定不要で使い始められる）。
2. 次の通知で「チャット#3『○○』が追加されました」とメインチャットに知らせる。
3. 同じ案件の別チャットは、メインチャットで `紐付け 3 案件名` とまとめる。元の案件にチャットが残らなければ、タスクごと統合して元の案件を削除する。
4. クライアントとのチャットは `種別 3 クライアント` で種別を設定する。AIへの入力や通知の根拠表示に「制作 / クライアント」として使う。

## 5. タスク抽出

### 5.1 解析タイミング
15分ごとに、未解析メッセージがある案件のうち以下を満たすものを解析する（1回最大5案件、並列）。
- 最後の発言から10分以上経過（会話が一段落した）
- または未解析が30件以上たまった

会話は複数の発言にまたがって成立する（「お願いできますか」→「金曜までに送ります」）ため、1発言ずつではなくまとめて解析する。

### 5.2 AIへの入力
- 今日の日付と曜日（JST）、案件名
- 案件内のチャット一覧（種別付き）、メンバー一覧
- 案件の未完了タスク（id・内容・担当・期限・候補かどうか）
- 直前の解析済み会話10件（文脈用）
- 新しい会話（最大200件。参照ID・時刻・チャット・発言者・本文）

### 5.3 AIの出力（JSON Schema で形式を固定）
```json
{"actions": [
  {"type": "create",   "task_id": null, "title": "見積書の送付", "assignee": "佐藤", "due": "2026-10-16",
   "evidence_refs": ["m3","m2"], "confidence": 0.9, "reason": "依頼と引き受けが明確"},
  {"type": "complete", "task_id": 10, "title": null, "assignee": null, "due": null,
   "evidence_refs": ["m4"], "confidence": 0.85, "reason": "送付済みの報告"}
]}
```

### 5.4 反映ルール
| 種類 | 確度 | 扱い |
|---|---|---|
| create | 0.8以上 | 自動登録し通知 |
| create | 0.5〜0.8 | 「候補」として登録し、メインチャットで [登録][無視] |
| create | 0.5未満 | 捨てる |
| update / complete | 0.7以上 | 既存の未完了タスクにのみ反映（存在しないIDは無視） |

- 担当者名はメンバーの表示名と照合（敬称を除き完全一致 → 部分一致で一意に決まれば紐付け）。決まらなければ名前だけ保存。
- 根拠の発言（チャット種別・発言者・本文の冒頭80字）をタスクに保存し、通知に表示する。
- 反映と「解析済み」の記録は1トランザクションで行う（DB関数 `apply_extraction`）。
- 一時的なエラー（API障害など）は未解析のまま残し、次回に再試行する。AIの安全機能で拒否された会話は、再試行しても結果が変わらないため解析済みにする。

## 6. メインチャット

### 6.1 更新の通知（毎朝6時）
```
🔔 タスク更新（10/09 14:00）

【ABC社 サイト制作】
🆕 #12 見積書の送付
　👤佐藤 ⏰10/16(金)
　💬[クライアント] 佐藤「承知しました、金曜までにお送りします」
✅ #10 トップページ修正案の送付（👤田中）
✏️ #8 ロゴ再送
　→ 期限 10/20(火)

【D社 LP】
❓ 候補 #15 サイトマップ確認（下のカードで登録/無視）
```
候補は別途カード（登録/無視ボタン）で送る。テキストとカードは1回のプッシュにまとめる。

### 6.2 サマリー（6時の通知に付ける）
期限切れ / 今日まで / 7日以内を一覧し、それ以降・期限未定は件数のみ表示。更新の通知と同じプッシュで送る。

### 6.3 コマンド
README の「メインチャットのコマンド」を参照。応答はすべて返信なので無料。

### 6.4 メインチャットの登録
管理用グループで `#メイン登録 <合言葉>` と送る。合言葉は環境変数 `MAIN_REGISTER_CODE`。他のグループから勝手に登録されないようにするため。

## 7. データモデル

| テーブル | 内容 |
|---|---|
| `projects` | 案件（id = 案件#、name は一意） |
| `chats` | LINEグループ（id = チャット#、project_id、kind = internal/client、active） |
| `members` / `chat_members` | LINEユーザーの表示名と、どのチャットにいるか（7日ごとに表示名を更新） |
| `messages` | 会話（1年保持。`processed_at` で解析済みを管理、`line_message_id` で重複防止） |
| `tasks` | タスク（id = タスク#、status = candidate/open/done/dismissed、根拠、確度） |
| `events` | タスク変更履歴＋通知キュー（`notified_at` が空のものを毎朝6時に送信） |
| `settings` | メインチャットのグループID |

詳細は `supabase/migrations/20261009000000_init.sql`。

## 8. 料金の目安

| 項目 | 内容 |
|---|---|
| LINE | 案件チャットには送信しないため、費用が出るのはメインチャットへのプッシュのみ（1日1回）。グループへのプッシュは**メンバー数分**カウントされる。例: 通知先3人 × 1回 × 30日 = 月90通で無料枠（月200通）に収まる。4人以上になる場合や通知回数を増やす場合はライトプラン等が必要 |
| Claude API | 15分単位でまとめて解析するため呼び出しは控えめ。既定は `claude-opus-5-5`。費用を抑えたい場合は `CLAUDE_MODEL` で Sonnet / Haiku に変更可能（精度は要確認） |
| Supabase | 会話1年分で数百MB程度の見込み。業務利用では Pro プランを推奨（無料枠は非アクティブ時の一時停止やバックアップの制限があるため） |

※ LINE・Claude API・Supabase とも料金は改定されるため、導入時に最新情報を確認する。

## 9. 注意点

- **過去ログは読めない**: ボットはグループ参加以降の発言のみ受け取る。
- **テキストのみ対象**: 画像・ファイル・スタンプは初期版では対象外。
- **送信取り消し**: 未解析のメッセージが取り消された場合は解析対象から外す。
- **プライバシー**: 会話内容を Claude API に送信する。ボットは案件チャットで告知しない方針。クライアントへの説明が必要かは運用側で判断する。
- **誤検出・見逃し**: ゼロにはならないため、根拠の引用・候補ボタン・メインチャットでの修正コマンドで人が補正できるようにしている。
- **Edge Function の実行時間**: 1回最大5案件を並列で解析する。案件が多い場合は残りを次の15分で処理する。
